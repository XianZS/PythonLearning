## 一、doctest核心概念与原理
### 1.1 什么是doctest
**doctest**是Python标准库内置的轻量级测试框架，它的独特设计理念是**"文档即测试，测试即文档"**。doctest会搜索文档字符串中看起来像交互式Python会话的片段，然后执行这些会话并验证实际输出是否与预期输出完全一致。

doctest的核心价值在于：
- 让文档保持最新：如果代码发生变化但文档没有更新，测试会失败
- 提供可执行的示例：用户可以直接复制文档中的示例运行
- 零额外学习成本：使用熟悉的Python交互式语法编写测试
- 无需额外安装：作为标准库的一部分，随Python一起发布

### 1.2 Python 3.14.0中doctest的特性
Python 3.14.0继承并完善了Python 3.13引入的重要改进：
- **默认彩色输出**：测试结果会根据成功/失败显示不同颜色，可通过`PYTHON_COLORS`、`NO_COLOR`和`FORCE_COLOR`环境变量控制
- **改进的差异显示**：使用`difflib.Differ`算法显示行内差异，更易发现细微差别
- **更好的异常信息处理**：修复了Python 3.13 beta版本中异常脱字符显示不一致的问题
- **完全支持PEP 649延迟注解**：正确解析和测试使用新注解语法的代码
- **支持PEP 750模板字符串(t-strings)**：可以在doctest中使用新的模板字符串语法

### 1.3 doctest的工作原理
doctest的执行过程分为三个核心阶段：
1. **解析阶段**：扫描模块、类或函数的文档字符串，提取所有以`>>>`开头的交互式会话
2. **执行阶段**：在一个独立的命名空间中逐行执行提取出的Python代码
3. **比较阶段**：将代码执行的实际输出与文档字符串中预期的输出进行逐字符比较

如果所有输出都匹配，测试通过；如果有任何不匹配，测试失败并显示详细的差异信息。

### 1.4 doctest vs unittest：适用场景对比
| 特性 | doctest | unittest |
|------|---------|----------|
| 编写方式 | 嵌入在文档字符串中 | 独立的测试方法 |
| 语法 | 交互式Python会话 | 断言方法调用 |
| 学习成本 | 极低 | 中等 |
| 测试能力 | 基础 | 强大 |
| 调试难度 | 较高 | 较低 |
| 文档价值 | 极高 | 低 |
| 适用场景 | 简单函数、工具类、文档示例 | 复杂系统、大型项目、集成测试 |

**最佳实践**：对于简单的工具函数和库，使用doctest作为文档和基本测试；对于复杂的业务逻辑和大型项目，使用unittest或pytest作为主要测试框架，doctest作为补充。

## 二、doctest基础使用
### 2.1 第一个doctest示例
让我们从一个最简单的加法函数开始，学习如何编写doctest：

```python
# first_doctest.py
def add(a, b):
    """
    计算两个数的和。
    
    >>> add(2, 3)
    5
    >>> add(-1, 1)
    0
    >>> add(0, 0)
    0
    """
    return a + b

if __name__ == "__main__":
    import doctest
    doctest.testmod()
```

这个示例中，我们在`add`函数的文档字符串中编写了三个测试用例，每个测试用例都模拟了Python交互式解释器的输入和输出。

### 2.3 基本语法规则
doctest有一套简单但严格的语法规则：
1. **测试输入**：必须以`>>>`开头，后面跟Python代码
2. **预期输出**：紧跟在测试输入后面，直到下一个`>>>`或空行
3. **空行**：表示一个测试用例的结束
4. **续行**：多行语句使用`...`作为提示符
5. **空白符**：默认情况下，输出中的空白符必须完全匹配

**多行语句示例**：
```python
def factorial(n):
    """
    计算n的阶乘。
    
    >>> factorial(5)
    120
    >>> for i in range(3):
    ...     print(factorial(i))
    1
    1
    2
    """
    if n < 0:
        raise ValueError("n必须是非负整数")
    result = 1
    for i in range(2, n+1):
        result *= i
    return result
```

### 2.4 异常测试的写法
doctest可以测试代码是否抛出预期的异常，只需要在预期输出中包含异常的类型和信息：

```python
def divide(a, b):
    """
    计算a除以b的结果。
    
    >>> divide(10, 2)
    5.0
    >>> divide(10, 0)
    Traceback (most recent call last):
        ...
    ZeroDivisionError: division by zero
    """
    return a / b
```

注意：异常信息中的堆栈跟踪部分可以使用`...`省略，因为堆栈跟踪包含文件路径和行号等可变信息。

### 2.5 空白符处理
默认情况下，doctest会逐字符比较输出，包括空白符。这意味着如果预期输出中有一个多余的空格，测试就会失败。

为了处理空白符的差异，doctest提供了`NORMALIZE_WHITESPACE`选项，我们将在进阶部分详细介绍。

## 三、doctest进阶使用
### 3.1 常用选项详解
doctest提供了多种选项来控制测试的行为，这些选项可以通过`optionflags`参数传递给`testmod()`或`testfile()`函数，也可以在文档字符串中使用`# doctest: +OPTION`的形式单独指定。

#### 3.1.1 NORMALIZE_WHITESPACE
忽略输出中的空白符差异，将多个连续的空白符视为一个：

```python
def print_list(lst):
    """
    打印列表中的元素。
    
    >>> print_list([1, 2, 3])
    1 2 3
    >>> print_list([1, 2, 3])  # doctest: +NORMALIZE_WHITESPACE
    1   2   3
    """
    print(' '.join(map(str, lst)))
```

#### 3.1.2 ELLIPSIS
使用`...`匹配任意字符串，非常适合处理包含可变内容的输出：

```python
import time

def get_current_time():
    """
    获取当前时间的字符串表示。
    
    >>> get_current_time()  # doctest: +ELLIPSIS
    'Current time: ...'
    """
    return f"Current time: {time.ctime()}"
```

#### 3.1.3 IGNORE_EXCEPTION_DETAIL
忽略异常信息中的详细内容，只检查异常类型：

```python
def parse_int(s):
    """
    将字符串解析为整数。
    
    >>> parse_int("abc")  # doctest: +IGNORE_EXCEPTION_DETAIL
    Traceback (most recent call last):
        ...
    ValueError:
    """
    return int(s)
```

#### 3.1.4 SKIP
跳过指定的测试用例：

```python
def slow_function():
    """
    一个执行时间很长的函数。
    
    >>> slow_function()  # doctest: +SKIP
    42
    """
    import time
    time.sleep(10)
    return 42
```

#### 3.1.5 REPORT_ONLY_FIRST_FAILURE
只报告第一个失败的测试用例：

```python
if __name__ == "__main__":
    import doctest
    doctest.testmod(optionflags=doctest.REPORT_ONLY_FIRST_FAILURE)
```

### 3.2 独立测试文件
对于较大的项目，可以将doctest写在单独的`.txt`文件中，而不是嵌入在文档字符串里。这样可以保持代码的简洁性，同时提供更详细的文档。

创建一个`math_functions.txt`文件：
```

-----------------

    ...

```

然后使用`doctest.testfile()`运行测试：
```python
# math_functions.py
def add(a, b):
    return a + b

def factorial(n):
    if n < 0:
        raise ValueError("n必须是非负整数")
    result = 1

```

运行方式：
```bash

```

或者直接使用命令行：
```bash
python -m doctest math_functions.txt -v
```

### 3.3 与unittest框架集成
doctest可以很容易地与unittest框架集成，这样你就可以使用unittest的所有功能来运行和管理doctest测试。

创建一个`test_math_functions.py`文件：
```python
import unittest
import doctest
import math_functions

def load_tests(loader, tests, ignore):
    """
    加载doctest测试用例到unittest测试套件中。
    """
    tests.addTests(doctest.DocTestSuite(math_functions))
    tests.addTests(doctest.DocFileSuite("math_functions.txt"))
    return tests

if __name__ == "__main__":
    unittest.main()
```

运行方式：
```bash
python test_math_functions.py -v
```

这样，doctest测试就会作为unittest测试用例的一部分运行，你可以使用unittest的所有命令行参数和功能。

### 3.4 高级语法技巧
#### 3.4.1 处理浮点数精度问题
浮点数的精度问题是doctest中常见的陷阱。由于浮点数的表示限制，实际输出可能与预期输出有微小的差异：

```python
def divide(a, b):
    """
    计算a除以b的结果。
    
    >>> divide(1, 3)  # 这个测试会失败！
    0.3333333333333333
    """
    return a / b
```

解决方法有两种：
1. 使用`ELLIPSIS`选项匹配部分输出
2. 使用`round()`函数四舍五入

```python
def divide(a, b):
    """
    计算a除以b的结果。
    
    >>> round(divide(1, 3), 6)
    0.333333
    >>> divide(1, 3)  # doctest: +ELLIPSIS
    0.333333...
    """
    return a / b
```

#### 3.4.2 处理对象表示
当测试返回对象的函数时，对象的默认表示通常包含内存地址，这是可变的：

```python
class Person:
    def __init__(self, name):
        self.name = name

def create_person(name):
    """
    创建一个Person对象。
    
    >>> create_person("Alice")  # 这个测试会失败！
    <__main__.Person object at 0x7f8b1c2d3a90>
    """
    return Person(name)
```

解决方法：
1. 为类定义`__repr__`方法
2. 使用`ELLIPSIS`选项忽略内存地址
3. 测试对象的属性而不是对象本身

```python
class Person:
    def __init__(self, name):
        self.name = name
    
    def __repr__(self):
        return f"Person(name='{self.name}')"

def create_person(name):
    """
    创建一个Person对象。
    
    >>> create_person("Alice")
    Person(name='Alice')
    >>> p = create_person("Bob")
    >>> p.name
    'Bob'
    """
    return Person(name)
```

#### 3.4.3 使用全局变量
在doctest中定义的变量默认是局部的，只在当前测试用例中有效。如果需要在多个测试用例之间共享变量，可以使用`globs`参数：

```python
if __name__ == "__main__":
    import doctest
    globs = {"x": 10, "y": 20}
    doctest.testmod(globs=globs)
```

然后在文档字符串中就可以使用这些全局变量：
```python
def multiply(a, b):
    """
    计算两个数的乘积。
    
    >>> multiply(x, y)
    200
    """
    return a * b
```

### 3.5 命令行参数详解
doctest模块支持多种命令行参数：

| 参数 | 功能描述 |
|------|----------|
| `-v`, `--verbose` | 显示详细的测试过程 |
| `-q`, `--quiet` | 只显示失败的测试 |
| `-f`, `--fail-fast` | 遇到第一个失败就停止 |
| `-o OPTION`, `--option OPTION` | 设置doctest选项 |
| `--no-color` | 禁用彩色输出 |
| `--force-color` | 强制启用彩色输出 |

示例：
```bash
# 只显示失败的测试
python -m doctest first_doctest.py -q

# 遇到第一个失败就停止
python -m doctest first_doctest.py -f

# 设置NORMALIZE_WHITESPACE选项
python -m doctest first_doctest.py -o NORMALIZE_WHITESPACE

# 禁用彩色输出
python -m doctest first_doctest.py --no-color
```

## 四、实战案例：测试字符串处理工具库
### 4.1 需求描述
我们将创建一个简单的字符串处理工具库，包含以下功能：
1. 字符串反转
2. 统计单词频率
3. 去除首尾空白和多余空格
4. 检查是否为回文字符串
5. 将字符串转换为驼峰命名法

每个函数都将包含详细的doctest，覆盖正常情况、边界条件和异常情况。

### 4.2 编写带doctest的代码
```python
# string_utils.py
import re
from collections import Counter

def reverse_string(s):
    """
    反转字符串。
    
    >>> reverse_string("hello")
    'olleh'
    >>> reverse_string("")
    ''
    >>> reverse_string("a")
    'a'
    >>> reverse_string("12345")
    '54321'
    """
    return s[::-1]

def count_word_frequency(s):
    """
    统计字符串中每个单词的出现频率。
    
    >>> count_word_frequency("hello world hello")
    {'hello': 2, 'world': 1}
    >>> count_word_frequency("")
    {}
    >>> count_word_frequency("a a a b b c")
    {'a': 3, 'b': 2, 'c': 1}
    >>> count_word_frequency("Hello hello HELLO")  # doctest: +NORMALIZE_WHITESPACE
    {'Hello': 1, 'hello': 1, 'HELLO': 1}
    """
    if not s:
        return {}
    words = s.split()
    return dict(Counter(words))

def clean_whitespace(s):
    """
    去除字符串首尾的空白，并将中间的多个空格替换为单个空格。
    
    >>> clean_whitespace("   hello   world   ")
    'hello world'
    >>> clean_whitespace("")
    ''
    >>> clean_whitespace("   ")
    ''
    >>> clean_whitespace("hello   world   foo")
    'hello world foo'
    """
    return ' '.join(s.split())

def is_palindrome(s):
    """
    检查字符串是否为回文（忽略大小写和非字母数字字符）。
    
    >>> is_palindrome("A man, a plan, a canal: Panama")
    True
    >>> is_palindrome("racecar")
    True
    >>> is_palindrome("hello")
    False
    >>> is_palindrome("")
    True
    >>> is_palindrome("a")
    True
    >>> is_palindrome("12321")
    True
    """
    # 移除非字母数字字符并转换为小写
    cleaned = re.sub(r'[^a-zA-Z0-9]', '', s).lower()
    return cleaned == cleaned[::-1]

def to_camel_case(s):
    """
    将下划线分隔的字符串转换为驼峰命名法。
    
    >>> to_camel_case("hello_world")
    'helloWorld'
    >>> to_camel_case("user_name_and_password")
    'userNameAndPassword'
    >>> to_camel_case("")
    ''
    >>> to_camel_case("a")
    'a'
    >>> to_camel_case("hello_world_123")
    'helloWorld123'
    """
    if not s:
        return ''
    words = s.split('_')
    return words[0] + ''.join(word.capitalize() for word in words[1:])

if __name__ == "__main__":
    import doctest
    # 运行所有doctest
    result = doctest.testmod(verbose=True)
    print(f"\n测试结果：{result.attempted}个测试，{result.failed}个失败")
```

## 五、总结与最佳实践
### 5.1 核心知识点回顾
- doctest是Python标准库内置的轻量级测试框架，实现了"文档即测试"的理念
- Python 3.14+支持默认彩色输出，可通过环境变量控制
- doctest的工作原理是解析文档字符串中的交互式会话并执行验证
- 三种运行方式：直接运行脚本、使用`python -m doctest`命令、在交互式解释器中运行
- 常用选项包括`NORMALIZE_WHITESPACE`、`ELLIPSIS`、`IGNORE_EXCEPTION_DETAIL`和`SKIP`
- 支持将测试写在独立的`.txt`文件中，并与unittest框架集成
- 常见问题包括浮点数精度、对象表示和空白符差异

### 5.2 最佳实践
1. **保持测试简单**：doctest适合测试简单的函数和方法，不要编写过于复杂的测试用例
2. **覆盖边界条件**：每个函数至少应该测试正常情况、边界条件和异常情况
3. **使用有意义的示例**：示例应该能够清晰地展示函数的用法和行为
4. **定期运行测试**：将doctest集成到开发流程和持续集成系统中
5. **结合其他测试框架**：对于复杂的项目，使用unittest或pytest作为主要测试框架，doctest作为补充
6. **使用选项处理特殊情况**：合理使用`ELLIPSIS`和`NORMALIZE_WHITESPACE`等选项处理可变输出
7. **为自定义类定义__repr__**：这样可以在doctest中方便地测试对象的表示

### 5.3 常见陷阱与解决方案
| 陷阱 | 解决方案 |
|------|----------|
| 浮点数精度差异 | 使用`round()`函数或`ELLIPSIS`选项 |
| 对象表示包含内存地址 | 定义`__repr__`方法或测试对象属性 |
| 空白符差异 | 使用`NORMALIZE_WHITESPACE`选项 |
| 异常信息包含可变内容 | 使用`IGNORE_EXCEPTION_DETAIL`选项 |
| 测试执行顺序依赖 | 每个测试用例应该独立，不依赖其他测试的结果 |
| 导入问题 | 在测试用例中显式导入需要的模块和函数 |
