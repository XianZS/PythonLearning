## 一、概念：为什么需要 `concurrent.futures`？
在之前的教程中，我们学习了 `threading`（多线程）和 `multiprocessing`（多进程），但它们的接口相对底层，需要手动管理线程/进程的创建、同步和结果回收。

`concurrent.futures` 是 Python 3.2+ 引入的**高层并发编程接口**，核心价值在于：
- **统一抽象**：用 `Executor` 接口封装线程池（`ThreadPoolExecutor`）和进程池（`ProcessPoolExecutor`），用法几乎一致；
- **简化流程**：无需手动 `start()`/`join()`，通过 `Future` 对象统一管理异步任务的状态和结果；
- **内置优化**：自动管理线程/进程的复用，减少创建/销毁开销。

### 核心组件
| 组件                     | 说明                                  |
|--------------------------|---------------------------------------|
| `Executor`               | 抽象基类，定义并发执行的接口          |
| `ThreadPoolExecutor`     | 线程池实现，适合 **I/O 密集型任务**   |
| `ProcessPoolExecutor`    | 进程池实现，适合 **CPU 密集型任务**   |
| `Future`                 | 代表异步任务的“未来结果”，可查询状态、获取结果 |


## 二、基础部分：核心用法
### 1. `ThreadPoolExecutor`：线程池基础
线程池适合处理网络请求、文件读写等 **I/O 密集型任务**（I/O 操作会释放 GIL，线程可并行等待）。

#### 1.1 提交单个任务：`submit()` + `Future.result()`
```python
import concurrent.futures
import time

def task(name, delay):
    """模拟 I/O 任务"""
    print(f"任务 {name} 开始（线程: {threading.current_thread().name}）")
    time.sleep(delay)
    print(f"任务 {name} 结束")
    return f"任务 {name} 的结果"

if __name__ == "__main__":
    import threading
    # 创建线程池（max_workers 为最大线程数，默认等于 CPU 核心数 * 5）
    with concurrent.futures.ThreadPoolExecutor(max_workers=2) as executor:
        # 提交任务：submit(函数, 参数1, 参数2, ...)，返回 Future 对象
        future1 = executor.submit(task, "A", 2)
        future2 = executor.submit(task, "B", 1)
        
        # 获取结果：result() 会阻塞直到任务完成
        print(future1.result())
        print(future2.result())
```

#### 1.2 批量提交任务：`map()`
`map()` 按任务提交顺序返回结果，适合批量处理同类型任务：
```python
def square(x):
    time.sleep(0.1)  # 模拟 I/O
    return x * x

if __name__ == "__main__":
    with concurrent.futures.ThreadPoolExecutor(max_workers=3) as executor:
        # map(函数, 可迭代对象)，按顺序返回结果
        results = executor.map(square, range(5))
        print("map 结果:", list(results))  # [0, 1, 4, 9, 16]
```

#### 1.3 按完成顺序获取结果：`as_completed()`
`map()` 按提交顺序返回，`as_completed()` 按**任务完成顺序**返回，更灵活：
```python
if __name__ == "__main__":
    with concurrent.futures.ThreadPoolExecutor(max_workers=2) as executor:
        # 提交多个任务，存储 Future 对象
        futures = {executor.submit(task, f"任务{i}", 2 - i % 2): f"任务{i}" for i in range(4)}
        
        # 按完成顺序遍历
        for future in concurrent.futures.as_completed(futures):
            task_name = futures[future]
            try:
                result = future.result()
                print(f"{task_name} 完成，结果: {result}")
            except Exception as e:
                print(f"{task_name} 出错: {e}")
```

### 2. `ProcessPoolExecutor`：进程池基础
进程池适合处理复杂计算、数据处理等 **CPU 密集型任务**（每个进程有独立 GIL，可真正并行）。

#### 注意事项
- Windows 平台必须加 `if __name__ == "__main__":`（与 `multiprocessing` 一致）；
- 传递给进程池的函数和参数必须支持 `pickle` 序列化；
- 进程创建开销比线程大，`max_workers` 建议等于 CPU 核心数（默认值）。

#### 示例：CPU 密集型任务（计算平方和）
```python
def cpu_task(x):
    """模拟 CPU 密集型计算"""
    total = 0
    for i in range(10**6):
        total += i
    return x * x

if __name__ == "__main__":
    # 单进程版本
    start = time.time()
    single_results = [cpu_task(x) for x in range(4)]
    print(f"单进程结果: {single_results}，耗时: {time.time() - start:.2f}s")
    
    # 多进程版本
    start = time.time()
    with concurrent.futures.ProcessPoolExecutor(max_workers=4) as executor:
        multi_results = list(executor.map(cpu_task, range(4)))
    print(f"多进程结果: {multi_results}，耗时: {time.time() - start:.2f}s")
```

### 3. `Future` 对象基础方法
`Future` 是异步任务的“句柄”，核心方法：
| 方法               | 说明                                  |
|--------------------|---------------------------------------|
| `done()`           | 判断任务是否完成（返回 True/False）   |
| `cancel()`         | 尝试取消未执行的任务（成功返回 True） |
| `result(timeout)` | 获取任务结果（timeout 为超时时间，阻塞直到完成） |
| `exception()`      | 获取任务抛出的异常（无异常返回 None） |

```python
if __name__ == "__main__":
    with concurrent.futures.ThreadPoolExecutor(max_workers=1) as executor:
        future = executor.submit(task, "A", 2)
        
        print("任务是否完成:", future.done())  # False
        # 尝试取消（如果任务还没开始）
        # print("取消任务:", future.cancel())
        print("任务结果:", future.result())  # 阻塞直到完成
        print("任务是否完成:", future.done())  # True
```


## 三、进阶部分：深度技巧
### 1. 上下文管理：自动关闭 `Executor`
用 `with` 语句管理 `Executor`，可自动调用 `shutdown(wait=True)`，确保所有任务完成后释放资源：
```python
# 推荐写法
with concurrent.futures.ThreadPoolExecutor() as executor:
    executor.submit(task, "A", 1)

# 等价于（不推荐手动写）
executor = concurrent.futures.ThreadPoolExecutor()
try:
    executor.submit(task, "A", 1)
finally:
    executor.shutdown(wait=True)
```

### 2. 回调函数：`add_done_callback()`
当 `Future` 完成时，自动执行回调函数（无需阻塞等待结果）：
```python
def save_result(future):
    """回调函数：保存任务结果"""
    try:
        result = future.result()
        print(f"回调函数收到结果: {result}")
    except Exception as e:
        print(f"回调函数捕获异常: {e}")

if __name__ == "__main__":
    with concurrent.futures.ThreadPoolExecutor() as executor:
        future = executor.submit(task, "A", 1)
        # 添加回调（任务完成后自动调用）
        future.add_done_callback(save_result)
        print("主线程继续执行，不阻塞")
        time.sleep(2)  # 等待回调执行
```

### 3. 异常处理进阶
#### 3.1 `submit()` 中的异常
异常会在调用 `result()` 时抛出，需手动捕获：
```python
def error_task():
    raise ValueError("任务出错了！")

if __name__ == "__main__":
    with concurrent.futures.ThreadPoolExecutor() as executor:
        future = executor.submit(error_task)
        try:
            future.result()
        except ValueError as e:
            print(f"捕获到异常: {e}")
```

#### 3.2 `map()` 中的异常
异常会在**迭代结果**时抛出，且会中断迭代：
```python
def maybe_error(x):
    if x == 2:
        raise ValueError(f"x={x} 出错了")
    return x * x

if __name__ == "__main__":
    with concurrent.futures.ThreadPoolExecutor() as executor:
        try:
            for result in executor.map(maybe_error, range(5)):
                print(result)
        except ValueError as e:
            print(f"迭代时捕获异常: {e}")
```

### 4. `wait()`：灵活等待多个任务
`wait()` 可等待多个 `Future` 完成，支持 `return_when` 参数控制等待条件：
| `return_when` 值       | 说明                                  |
|-------------------------|---------------------------------------|
| `FIRST_COMPLETED`      | 等待第一个任务完成或出错             |
| `ALL_COMPLETED`        | 等待所有任务完成（默认值）           |
| `FIRST_EXCEPTION`      | 等待第一个任务出错（无出错则等所有完成） |

```python
if __name__ == "__main__":
    with concurrent.futures.ThreadPoolExecutor(max_workers=2) as executor:
        futures = [executor.submit(task, f"任务{i}", 2 - i % 2) for i in range(4)]
        
        # 等待第一个完成的任务
        done, not_done = concurrent.futures.wait(
            futures,
            return_when=concurrent.futures.FIRST_COMPLETED
        )
        
        print(f"已完成任务数: {len(done)}，未完成任务数: {len(not_done)}")
        # 处理已完成的任务
        for future in done:
            print(future.result())
```

### 5. `ProcessPoolExecutor` 高级参数
#### 5.1 `mp_context`：设置进程启动方法
Python 3.14 中可通过 `mp_context` 指定进程启动方式（如 `spawn`/`fork`），提高跨平台兼容性：
```python
if __name__ == "__main__":
    import multiprocessing
    # 创建 spawn 方式的上下文
    ctx = multiprocessing.get_context("spawn")
    # 传入 ProcessPoolExecutor
    with concurrent.futures.ProcessPoolExecutor(mp_context=ctx) as executor:
        results = list(executor.map(cpu_task, range(4)))
```

#### 5.2 `initializer` + `initargs`：进程初始化
可在进程启动时执行初始化函数（如加载全局配置）：
```python
def init_process(config):
    """进程初始化函数"""
    global GLOBAL_CONFIG
    GLOBAL_CONFIG = config
    print(f"进程初始化完成，配置: {GLOBAL_CONFIG}")

def task_with_config(x):
    return x * GLOBAL_CONFIG["scale"]

if __name__ == "__main__":
    config = {"scale": 2}
    with concurrent.futures.ProcessPoolExecutor(
        initializer=init_process,
        initargs=(config,)
    ) as executor:
        results = list(executor.map(task_with_config, range(4)))
        print("结果:", results)  # [0, 2, 4, 6]
```


## 四、实战案例：批量图片下载与灰度处理
### 需求
结合 `ThreadPoolExecutor`（I/O 密集：下载图片）和 `ProcessPoolExecutor`（CPU 密集：转灰度），实现一个高效的批量图片处理工具。

### 代码实现
```python
import concurrent.futures
import requests
import os
from PIL import Image
import time

# ---------------------- 配置 ----------------------
IMAGE_URLS = [
    "https://picsum.photos/200/300?random=1",
    "https://picsum.photos/200/300?random=2",
    "https://picsum.photos/200/300?random=3",
    "https://picsum.photos/200/300?random=4",
]
DOWNLOAD_DIR = "downloaded_images"
GRAYSCALE_DIR = "grayscale_images"
os.makedirs(DOWNLOAD_DIR, exist_ok=True)
os.makedirs(GRAYSCALE_DIR, exist_ok=True)

# ---------------------- 步骤 1：多线程下载图片（I/O 密集） ----------------------
def download_image(url):
    """下载单张图片，返回保存路径"""
    try:
        response = requests.get(url, timeout=10)
        response.raise_for_status()
        filename = f"img_{hash(url) % 10000}.jpg"
        save_path = os.path.join(DOWNLOAD_DIR, filename)
        with open(save_path, "wb") as f:
            f.write(response.content)
        print(f"下载完成: {filename}")
        return save_path
    except Exception as e:
        print(f"下载失败 {url}: {e}")
        return None

# ---------------------- 步骤 2：多进程转灰度（CPU 密集） ----------------------
def to_grayscale(image_path):
    """将图片转为灰度，返回新路径"""
    if not image_path:
        return None
    try:
        with Image.open(image_path) as img:
            gray_img = img.convert("L")
            filename = os.path.basename(image_path)
            save_path = os.path.join(GRAYSCALE_DIR, f"gray_{filename}")
            gray_img.save(save_path)
            print(f"灰度处理完成: {filename}")
            return save_path
    except Exception as e:
        print(f"灰度处理失败 {image_path}: {e}")
        return None

# ---------------------- 主流程 ----------------------
if __name__ == "__main__":
    start = time.time()
    
    # 1. 多线程下载
    print("=== 开始下载图片 ===")
    with concurrent.futures.ThreadPoolExecutor(max_workers=4) as executor:
        download_paths = list(executor.map(download_image, IMAGE_URLS))
    
    # 2. 多进程转灰度
    print("\n=== 开始灰度处理 ===")
    with concurrent.futures.ProcessPoolExecutor() as executor:
        gray_paths = list(executor.map(to_grayscale, download_paths))
    
    # 3. 汇总结果
    print("\n=== 处理完成 ===")
    success_count = sum(1 for p in gray_paths if p)
    print(f"成功处理 {success_count}/{len(IMAGE_URLS)} 张图片")
    print(f"总耗时: {time.time() - start:.2f}s")
```


## 五、总结
1. **核心选择**：
   - **I/O 密集型任务**（下载、文件读写）：用 `ThreadPoolExecutor`；
   - **CPU 密集型任务**（计算、数据处理）：用 `ProcessPoolExecutor`。
2. **核心用法**：
   - 批量任务用 `map()`，灵活任务用 `submit()` + `as_completed()`/`wait()`；
   - 回调函数 `add_done_callback()` 可异步处理结果；
   - 注意进程池的序列化和跨平台问题。
3. **优势**：`concurrent.futures` 封装了底层细节，让并发编程更简洁、不易出错。
