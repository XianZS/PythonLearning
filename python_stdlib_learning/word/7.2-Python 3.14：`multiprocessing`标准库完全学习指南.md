# Python 3.14 `multiprocessing` 标准库完全学习指南

## 一、概念：为什么需要 `multiprocessing`？

### 1. 从 GIL 说起

在 [threading 教程](https://www.bilibili.com) 中我们讲过，**CPython 解释器存在全局解释器锁（GIL）**：同一时刻只有一个线程能执行 Python 字节码。这意味着：

- **I/O 密集型任务**（如网络请求、文件读写）：多线程可通过 “GIL 在 I/O 时释放” 提升效率。

- **CPU 密集型任务**（如复杂计算、数据处理）：多线程无法实现真正并行，甚至因线程切换开销变慢。

### 2. `multiprocessing` 的核心价值

`multiprocessing` 通过**多进程**实现真正的并行计算：

- 每个进程有独立的 Python 解释器和 GIL，互不干扰；

- 进程间内存空间独立，需通过特定机制通信；

- 完美适配 **CPU 密集型任务**，充分利用多核 CPU 性能。

### 3. 进程 vs 线程对比

|维度|进程|线程|
|---|---|---|
|资源开销|大（独立内存空间、文件句柄等）|小（共享进程内存）|
|通信难度|高（需 IPC 机制）|低（直接读写共享变量）|
|GIL 影响|无（每个进程有独立 GIL）|有（同一进程内线程共享 GIL）|
|适用场景|CPU 密集型任务|I/O 密集型任务|

## 二、基础部分：核心用法

### 1. 进程创建的两种方式

#### 方式 1：直接实例化 `Process` 类（推荐，简单场景）

```python
import multiprocessing
import time
import os

def task(name, delay):
    """进程执行的任务"""
    print(f"进程 {name} 启动（PID: {os.getpid()}，父进程 PID: {os.getppid()}）")
    time.sleep(delay)  # 模拟 CPU 计算
    print(f"进程 {name} 结束（耗时 {delay}s）")

if __name__ == "__main__":
    # 注意：Windows 平台必须加 `if __name__ == "__main__":`，否则会无限递归创建进程
    
    # 创建进程：target 是任务函数，args 是参数元组
    p1 = multiprocessing.Process(target=task, args=("A", 2))
    p2 = multiprocessing.Process(target=task, args=("B", 1))

    # 启动进程（调用 start() 后才会真正执行）
    p1.start()
    p2.start()

    # 等待进程结束（join() 会阻塞主进程，直到子进程执行完毕）
    p1.join()
    p2.join()

    print("所有进程执行完毕")
```

#### 方式 2：继承 `Process` 类，重写 `run()` 方法（复杂场景）

```python
class MyProcess(multiprocessing.Process):
    def __init__(self, name, delay):
        super().__init__()  # 必须调用父类构造函数
        self.name = name
        self.delay = delay

    def run(self):
        """进程执行的逻辑（start() 会自动调用 run()）"""
        print(f"进程 {self.name} 启动（PID: {os.getpid()}）")
        time.sleep(self.delay)
        print(f"进程 {self.name} 结束")

if __name__ == "__main__":
    p1 = MyProcess("A", 2)
    p2 = MyProcess("B", 1)
    p1.start()
    p2.start()
    p1.join()
    p2.join()
```

### 2. 进程启动方法（重要！跨平台兼容性）

`multiprocessing` 支持 3 种进程启动方式，可通过 `set_start_method()` 设置：

```python
if __name__ == "__main__":
    # 设置启动方式（必须在创建进程前调用）
    multiprocessing.set_start_method('spawn')  # 推荐，跨平台兼容性最好
    
    # 查看当前启动方式
    print("当前启动方式:", multiprocessing.get_start_method())
```

|启动方式|说明|平台支持|优缺点|
|---|---|---|---|
|`spawn`|父进程启动新的 Python 解释器，仅传递必要资源|Windows/macOS/Linux|安全、跨平台好，但启动速度慢|
|`fork`|直接复制父进程的所有资源（包括内存）|Linux（默认）|启动速度快，但在 macOS/Windows 上不稳定|
|`forkserver`|启动一个服务器进程，后续进程由服务器创建|Linux（部分场景）|平衡安全与速度，但配置复杂|

### 3. 核心基础属性与方法

|属性 / 方法|说明|
|---|---|
|`multiprocessing.current_process()`|获取当前执行的进程对象|
|`process.pid`|进程 ID（PID）|
|`process.name`|进程名（可通过构造函数或 `name` 参数设置）|
|`process.is_alive()`|判断进程是否仍在运行|
|`process.daemon`|守护进程标记（主进程结束时自动终止守护进程）|

## 三、进阶部分：深度技巧与进程间通信

多进程的核心难点是**进程间内存独立**，需通过特定机制实现通信（IPC）和同步。

### 1. 进程间通信（IPC）：`Queue`（最常用）

`Queue` 是线程 / 进程安全的队列，用于在进程间传递数据（数据会被序列化）：

```python
import multiprocessing

def producer(q):
    """生产者：向队列中放入数据"""
    for i in range(5):
        q.put(i)
        print(f"生产者放入数据: {i}")

def consumer(q):
    """消费者：从队列中取出数据"""
    while True:
        data = q.get()  # 队列为空时会阻塞
        if data is None:  # 用 None 作为结束标记
            break
        print(f"消费者取出数据: {data}")

if __name__ == "__main__":
    # 创建队列
    q = multiprocessing.Queue()
    
    # 创建生产者和消费者进程
    p_prod = multiprocessing.Process(target=producer, args=(q,))
    p_cons = multiprocessing.Process(target=consumer, args=(q,))
    
    p_prod.start()
    p_cons.start()
    
    p_prod.join()
    q.put(None)  # 发送结束标记
    p_cons.join()
```

### 2. 进程间通信：`Pipe`（双向管道）

`Pipe` 用于两个进程之间的双向通信，返回一对连接对象 `(conn1, conn2)`：

```python
import multiprocessing

def sender(conn):
    """发送方：通过管道发送数据"""
    conn.send("Hello from sender!")
    conn.send([1, 2, 3])
    conn.close()

def receiver(conn):
    """接收方：通过管道接收数据"""
    while True:
        try:
            data = conn.recv()  # 管道关闭时会抛出 EOFError
            print(f"接收方收到数据: {data}")
        except EOFError:
            break

if __name__ == "__main__":
    # 创建管道（duplex=True 表示双向，False 表示单向）
    parent_conn, child_conn = multiprocessing.Pipe(duplex=True)
    
    p_sender = multiprocessing.Process(target=sender, args=(child_conn,))
    p_receiver = multiprocessing.Process(target=receiver, args=(parent_conn,))
    
    p_sender.start()
    p_receiver.start()
    
    p_sender.join()
    p_receiver.join()
```

### 3. 进程间通信：`Manager`（共享对象）

`Manager` 可创建共享的 Python 对象（如列表、字典），供多个进程访问：

```python
import multiprocessing

def modify_list(shared_list, lock):
    """修改共享列表"""
    with lock:  # 加锁保证数据一致性
        shared_list.append(multiprocessing.current_process().name)
        print(f"当前共享列表: {shared_list}")

if __name__ == "__main__":
    # 创建 Manager 对象
    with multiprocessing.Manager() as manager:
        # 创建共享列表和锁
        shared_list = manager.list()
        lock = multiprocessing.Lock()
        
        # 创建多个进程修改共享列表
        processes = []
        for i in range(3):
            p = multiprocessing.Process(target=modify_list, args=(shared_list, lock), name=f"进程-{i+1}")
            processes.append(p)
            p.start()
        
        for p in processes:
            p.join()
        
        print(f"最终共享列表: {shared_list}")
```

### 4. 进程同步：`Lock`（解决资源竞争）

虽然进程内存独立，但在访问共享资源（如文件、共享对象）时仍需加锁：

```python
import multiprocessing

def increment(shared_value, lock):
    """对共享变量进行累加"""
    for _ in range(100000):
        with lock:  # with 语句会自动获取/释放锁
            shared_value.value += 1

if __name__ == "__main__":
    # 创建共享变量（'i' 表示整数类型）
    shared_value = multiprocessing.Value('i', 0)
    lock = multiprocessing.Lock()
    
    p1 = multiprocessing.Process(target=increment, args=(shared_value, lock))
    p2 = multiprocessing.Process(target=increment, args=(shared_value, lock))
    
    p1.start()
    p2.start()
    p1.join()
    p2.join()
    
    print(f"最终共享变量值: {shared_value.value}")  # 无锁时结果可能小于 200000
```

### 5. 进程池：`Pool`（批量管理进程）

当需要创建大量进程时，用 `Pool` 可避免进程创建 / 销毁的开销，实现进程复用：

```python
import multiprocessing
import time

def square(x):
    """计算平方（模拟 CPU 密集型任务）"""
    time.sleep(0.1)
    return x * x

if __name__ == "__main__":
    # 创建进程池（processes 参数指定进程数，默认等于 CPU 核心数）
    with multiprocessing.Pool(processes=4) as pool:
        # ---------------------- map：批量提交任务，阻塞等待结果 ----------------------
        start = time.time()
        results_map = pool.map(square, range(10))
        print(f"map 结果: {results_map}，耗时: {time.time() - start:.2f}s")
        
        # ---------------------- apply_async：单个提交任务，异步获取结果 ----------------------
        start = time.time()
        results_async = [pool.apply_async(square, args=(i,)) for i in range(10)]
        # 获取结果（get() 会阻塞）
        results_async = [res.get() for res in results_async]
        print(f"apply_async 结果: {results_async}，耗时: {time.time() - start:.2f}s")
        
        # ---------------------- imap_unordered：批量提交，结果按完成顺序返回 ----------------------
        start = time.time()
        results_unordered = list(pool.imap_unordered(square, range(10)))
        print(f"imap_unordered 结果: {results_unordered}，耗时: {time.time() - start:.2f}s")
```

### 6. 注意事项（避坑指南）

1. **必须加 ****`if __name__ == &#34;__main__&#34;:`**：Windows 平台会重新导入模块，不加会无限递归创建进程。

2. **避免用全局变量共享数据**：进程内存独立，全局变量在每个进程中是独立副本，需用 IPC 机制。

3. **对象必须可序列化**：通过 `Queue`/`Pipe` 传递的对象需支持 `pickle` 序列化（如 lambda 函数不可序列化）。

4. **及时关闭资源**：`Pool`、`Manager` 等对象建议用 `with` 语句管理，自动释放资源。

## 四、实战案例：并行计算蒙特卡洛方法求 π

### 需求

用**蒙特卡洛方法**计算圆周率 π，对比单进程与多进程的性能差异。

#### 原理

在边长为 1 的正方形内随机投点，点落在四分之一圆内的概率为 `π/4`，因此：

```Plain Text
π ≈ 4 × (落在圆内的点数 / 总投点数)
```

### 代码实现

```python
import multiprocessing
import random
import time

def monte_carlo_part(n):
    """
    单进程计算部分投点结果
    :param n: 该进程的投点次数
    :return: 落在圆内的点数
    """
    count = 0
    # 每个进程用独立的随机种子，避免重复
    random.seed()
    for _ in range(n):
        x = random.random()
        y = random.random()
        if x * x + y * y <= 1:
            count += 1
    return count

def single_process(total_points):
    """单进程版本"""
    start = time.time()
    count = monte_carlo_part(total_points)
    pi = 4 * count / total_points
    print(f"单进程结果: π ≈ {pi:.8f}，耗时: {time.time() - start:.2f}s")
    return pi

def multi_process(total_points, process_count):
    """多进程版本"""
    start = time.time()
    # 将总投点次数分配给多个进程
    points_per_process = total_points // process_count
    # 创建进程池
    with multiprocessing.Pool(processes=process_count) as pool:
        # 批量提交任务
        counts = pool.map(monte_carlo_part, [points_per_process] * process_count)
    # 汇总结果
    total_count = sum(counts)
    pi = 4 * total_count / total_points
    print(f"多进程结果: π ≈ {pi:.8f}，耗时: {time.time() - start:.2f}s（进程数: {process_count}）")
    return pi

if __name__ == "__main__":
    # 配置参数
    TOTAL_POINTS = 10_000_000  # 总投点次数（越大结果越精确）
    PROCESS_COUNT = multiprocessing.cpu_count()  # 进程数等于 CPU 核心数
    
    print(f"=== 蒙特卡洛方法求 π（总投点次数: {TOTAL_POINTS:,}）===n")
    
    # 单进程测试
    single_process(TOTAL_POINTS)
    
    # 多进程测试
    multi_process(TOTAL_POINTS, PROCESS_COUNT)
```

### 运行结果示例（4 核 CPU）

```Plain Text
=== 蒙特卡洛方法求 π（总投点次数: 10,000,000）===

单进程结果: π ≈ 3.14152360，耗时: 2.15s
多进程结果: π ≈ 3.14167840，耗时: 0.58s（进程数: 4）
```

可以看到，多进程版本充分利用了多核 CPU，耗时约为单进程的 1/4。

## 五、总结

1. **适用场景**：`multiprocessing` 是 **CPU 密集型任务**的首选，可充分利用多核 CPU 性能。

2. **核心要点**：

    - 进程创建用 `Process` 类，Windows 平台必须加 `if __name__ == &#34;__main__&#34;:`。

    - 进程间通信优先用 `Queue`，共享对象用 `Manager`，双向通信用 `Pipe`。

    - 批量任务用 `Pool` 管理进程，减少创建 / 销毁开销。

3. **避坑提醒**：避免全局变量共享数据，确保传递对象可序列化，及时关闭资源。
