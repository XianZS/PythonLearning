# Python 3.14.0 unittest标准库完整学习文档

## 一、unittest核心概念与原理
### 1.1 什么是unittest
**unittest**（又称PyUnit）是Python标准库内置的单元测试框架，基于xUnit测试架构设计，提供了一套完整的测试用例编写、组织、运行和结果展示体系。它是Python官方推荐的单元测试工具，无需额外安装，广泛应用于Python项目的自动化测试中。

unittest的核心价值在于：
- 确保代码的正确性和稳定性
- 便于代码重构和维护
- 提供清晰的代码行为文档
- 支持自动化测试和持续集成

### 1.2 Python 3.14.0中unittest的新特性
Python 3.14.0对unittest进行了多项重要改进，提升了测试体验和功能完整性：
- **完全支持PEP 695泛型语法测试**：可以正确测试泛型类、泛型函数和类型参数
- **新增`assertSequenceEqual(strict=True)`参数**：强制要求序列类型完全匹配（区分`list`和`tuple`）
- **增强`assertDictEqual`错误信息**：显示更详细的键值对差异对比，支持嵌套字典
- **优化测试发现机制**：在嵌套包中更准确地发现测试模块，支持符号链接目录
- **改进异步测试性能**：`IsolatedAsyncioTestCase`的执行速度提升约30%
- **新增`--no-header`命令行选项**：运行测试时不显示版本和平台信息
- **修复`mock.patch`类方法修补问题**：解决了在某些情况下无法正确修补静态方法和类方法的bug
- **修复嵌套`subTest`上下文管理问题**：现在可以正确处理多层嵌套的子测试

### 1.3 unittest核心架构
unittest由五个核心组件构成，形成了完整的测试流程：

| 组件 | 功能描述 |
|------|----------|
| `TestCase` | 测试用例的基类，所有测试类都需要继承它 |
| `TestSuite` | 测试套件，用于组织多个测试用例或测试套件 |
| `TestLoader` | 测试加载器，用于自动发现和加载测试用例 |
| `TestRunner` | 测试运行器，负责执行测试并生成结果 |
| `TestResult` | 测试结果，用于收集和存储测试执行信息 |

### 1.4 xUnit四阶段测试模式
unittest遵循xUnit架构的四阶段测试模式，每个测试用例都应该包含以下四个步骤：
1. **准备（Arrange）**：初始化测试环境和数据
2. **执行（Act）**：调用待测试的代码
3. **断言（Assert）**：验证结果是否符合预期
4. **清理（Cleanup）**：恢复测试环境，避免影响其他测试

## 二、unittest基础使用
### 2.1 第一个测试用例
编写unittest测试用例的基本步骤：
1. 导入`unittest`模块
2. 创建继承自`unittest.TestCase`的测试类
3. 在测试类中定义以`test_`开头的测试方法
4. 在测试方法中使用断言方法验证结果

```python
# first_test.py
import unittest

def add(a, b):
    """待测试的加法函数"""
    return a + b

class TestAddFunction(unittest.TestCase):
    """测试add函数的测试类"""
    
    def test_add_positive_numbers(self):
        """测试两个正数相加"""
        result = add(2, 3)
        self.assertEqual(result, 5)
    
    def test_add_negative_numbers(self):
        """测试两个负数相加"""
        result = add(-2, -3)
        self.assertEqual(result, -5)
    
    def test_add_zero(self):
        """测试与零相加"""
        result = add(0, 5)
        self.assertEqual(result, 5)

if __name__ == '__main__':
    unittest.main()
```

运行测试：
```bash
python first_test.py
```

输出结果：
```
...
----------------------------------------------------------------------
Ran 3 tests in 0.000s

OK
```

### 2.2 基本断言方法
unittest提供了丰富的断言方法，用于验证测试结果。以下是最常用的断言：

| 断言方法 | 功能描述 |
|---------|----------|
| `assertEqual(a, b)` | 验证`a == b` |
| `assertNotEqual(a, b)` | 验证`a != b` |
| `assertTrue(x)` | 验证`x is True` |
| `assertFalse(x)` | 验证`x is False` |
| `assertIs(a, b)` | 验证`a is b`（同一对象） |
| `assertIsNot(a, b)` | 验证`a is not b` |
| `assertIsNone(x)` | 验证`x is None` |
| `assertIsNotNone(x)` | 验证`x is not None` |
| `assertIn(a, b)` | 验证`a in b` |
| `assertNotIn(a, b)` | 验证`a not in b` |
| `assertIsInstance(a, b)` | 验证`isinstance(a, b)` |
| `assertNotIsInstance(a, b)` | 验证`not isinstance(a, b)` |
| `assertSequenceEqual(a, b, strict=True)` | 验证序列相等（3.14+支持strict参数） |
| `assertDictEqual(a, b)` | 验证字典相等 |
| `assertListEqual(a, b)` | 验证列表相等 |
| `assertTupleEqual(a, b)` | 验证元组相等 |

**Python 3.14+新特性示例：`assertSequenceEqual(strict=True)`**
```python
# strict_sequence_test.py
import unittest

class TestStrictSequence(unittest.TestCase):
    def test_sequence_strict(self):
        list1 = [1, 2, 3]
        tuple1 = (1, 2, 3)
        
        # 不使用strict参数，只比较内容，不比较类型
        self.assertSequenceEqual(list1, tuple1)  # 通过
        
        # 使用strict=True，同时比较内容和类型
        with self.assertRaises(AssertionError):
            self.assertSequenceEqual(list1, tuple1, strict=True)  # 失败

if __name__ == '__main__':
    unittest.main()
```

### 2.3 测试固件（Test Fixtures）
测试固件用于在测试执行前后进行准备和清理工作，确保测试环境的独立性。unittest提供了四个级别的测试固件：

#### 方法级固件：`setUp()`和`tearDown()`
在**每个测试方法**执行前后分别调用：
```python
# fixture_test.py
import unittest

class TestCalculator(unittest.TestCase):
    def setUp(self):
        """每个测试方法执行前调用"""
        print("准备测试环境")
        self.calculator = {"add": lambda a, b: a + b, "subtract": lambda a, b: a - b}
    
    def tearDown(self):
        """每个测试方法执行后调用"""
        print("清理测试环境")
        del self.calculator
    
    def test_add(self):
        result = self.calculator["add"](2, 3)
        self.assertEqual(result, 5)
    
    def test_subtract(self):
        result = self.calculator["subtract"](5, 3)
        self.assertEqual(result, 2)

if __name__ == '__main__':
    unittest.main()
```

#### 类级固件：`setUpClass()`和`tearDownClass()`
在**整个测试类**执行前后分别调用一次，需要使用`@classmethod`装饰：
```python
class TestDatabase(unittest.TestCase):
    @classmethod
    def setUpClass(cls):
        """测试类执行前调用一次"""
        print("连接数据库")
        cls.db_connection = {"connected": True}
    
    @classmethod
    def tearDownClass(cls):
        """测试类执行后调用一次"""
        print("断开数据库连接")
        cls.db_connection["connected"] = False
    
    def test_connection(self):
        self.assertTrue(self.db_connection["connected"])
    
    def test_query(self):
        self.assertTrue(self.db_connection["connected"])
```

#### 模块级固件：`setUpModule()`和`tearDownModule()`
在**整个模块**执行前后分别调用一次：
```python
def setUpModule():
    """模块执行前调用一次"""
    print("初始化模块级资源")
    global config
    config = {"debug": True}

def tearDownModule():
    """模块执行后调用一次"""
    print("清理模块级资源")
    global config
    del config

class TestConfig(unittest.TestCase):
    def test_debug_mode(self):
        self.assertTrue(config["debug"])
```

## 三、unittest进阶使用
### 3.1 测试套件与测试组织
当测试用例数量较多时，可以使用`TestSuite`将测试用例组织成逻辑组：

```python
# test_suite.py
import unittest

class TestMathOperations(unittest.TestCase):
    def test_add(self):
        self.assertEqual(2+3, 5)
    
    def test_subtract(self):
        self.assertEqual(5-3, 2)

class TestStringOperations(unittest.TestCase):
    def test_upper(self):
        self.assertEqual('hello'.upper(), 'HELLO')
    
    def test_isupper(self):
        self.assertTrue('HELLO'.isupper())
        self.assertFalse('Hello'.isupper())

def create_test_suite():
    """创建测试套件"""
    suite = unittest.TestSuite()
    
    # 添加单个测试方法
    suite.addTest(TestMathOperations('test_add'))
    
    # 添加整个测试类
    math_tests = unittest.TestLoader().loadTestsFromTestCase(TestMathOperations)
    suite.addTest(math_tests)
    
    # 添加多个测试类
    string_tests = unittest.TestLoader().loadTestsFromTestCase(TestStringOperations)
    suite.addTests([math_tests, string_tests])
    
    return suite

if __name__ == '__main__':
    suite = create_test_suite()
    runner = unittest.TextTestRunner(verbosity=2)
    runner.run(suite)
```

### 3.2 跳过测试与预期失败
unittest提供了装饰器来控制测试的执行：

```python
# skip_test.py
import unittest
import sys

class TestSkipExamples(unittest.TestCase):
    # 无条件跳过测试
    @unittest.skip("跳过这个测试")
    def test_skip(self):
        self.fail("这个测试不会执行")
    
    # 条件跳过测试
    @unittest.skipIf(sys.version_info < (3, 14), "需要Python 3.14或更高版本")
    def test_skip_if(self):
        self.assertTrue(True)
    
    # 条件不满足时跳过测试
    @unittest.skipUnless(sys.platform.startswith("win"), "仅在Windows系统上运行")
    def test_skip_unless(self):
        self.assertTrue(True)
    
    # 预期测试失败
    @unittest.expectedFailure
    def test_expected_failure(self):
        self.assertEqual(1, 0)  # 这个失败是预期的，不会被计为失败
    
    # 意外成功（预期失败但实际通过）
    @unittest.expectedFailure
    def test_unexpected_success(self):
        self.assertEqual(1, 1)  # 这个会被计为意外成功

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

运行结果：
```

test_skip (skip_test.TestSkipExamples) ... skipped '跳过这个测试'
test_skip_if (skip_test.TestSkipExamples) ... ok
test_skip_unless (skip_test.TestSkipExamples) ... skipped '仅在Windows系统上运行'
test_unexpected_success (skip_test.TestSkipExamples) ... unexpected success

----------------------------------------------------------------------
Ran 5 tests in 0.001s

OK (skipped=2, expected failures=1, unexpected successes=1)
```

### 3.3 参数化测试
参数化测试允许使用不同的输入数据多次运行同一个测试方法，unittest提供了两种方式：

#### 方式1：使用`subTest`上下文管理器（标准库内置）
```python
# parameterized_test.py
import unittest

def is_even(n):
    """判断一个数是否为偶数"""
    return n % 2 == 0

class TestIsEven(unittest.TestCase):
    def test_is_even(self):
        test_cases = [
            (2, True, "偶数"),
            (3, False, "奇数"),
            (0, True, "零"),
            (-4, True, "负偶数"),
            (-5, False, "负奇数")
        ]
        
        for n, expected, description in test_cases:
            with self.subTest(n=n, description=description):
                self.assertEqual(is_even(n), expected)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

#### 方式2：使用第三方`parameterized`库（更强大）
```bash
pip install parameterized
```

```python
# parameterized_lib_test.py
import unittest
from parameterized import parameterized

def multiply(a, b):
    return a * b

class TestMultiply(unittest.TestCase):
    @parameterized.expand([
        ("positive", 2, 3, 6),
        ("negative", -2, -3, 6),
        ("mixed", 2, -3, -6),
        ("zero", 0, 5, 0),
    ])
    def test_multiply(self, name, a, b, expected):
        self.assertEqual(multiply(a, b), expected)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

### 3.4 异常测试
使用`assertRaises`上下文管理器或装饰器来测试代码是否抛出预期的异常：

```python
# exception_test.py
import unittest

def divide(a, b):
    if b == 0:
        raise ZeroDivisionError("除数不能为零")
    return a / b

class TestDivide(unittest.TestCase):
    # 方式1：使用上下文管理器
    def test_divide_by_zero_context(self):
        with self.assertRaises(ZeroDivisionError) as cm:
            divide(10, 0)
        
        # 验证异常信息
        self.assertEqual(str(cm.exception), "除数不能为零")
    
    # 方式2：使用装饰器
    @unittest.expectedFailure
    def test_divide_by_zero_decorator(self):
        divide(10, 0)
    
    # 测试不抛出异常的情况
    def test_divide_normal(self):
        result = divide(10, 2)
        self.assertEqual(result, 5)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

### 3.5 unittest.mock模拟对象
`unittest.mock`是unittest的子模块，用于创建模拟对象来替代测试中的依赖项，是单元测试中最强大的工具之一。

#### 3.5.1 基本模拟对象：`MagicMock`
```python
# mock_basic.py
import unittest
from unittest.mock import MagicMock

class TestMock(unittest.TestCase):
    def test_mock_return_value(self):
        # 创建模拟对象并设置返回值
        mock_func = MagicMock(return_value=42)
        
        # 调用模拟对象
        result = mock_func(1, 2, 3)
        
        # 验证返回值
        self.assertEqual(result, 42)
        
        # 验证调用情况
        mock_func.assert_called_once_with(1, 2, 3)
    
    def test_mock_side_effect(self):
        # 设置副作用：抛出异常
        mock_func = MagicMock(side_effect=ValueError("无效参数"))
        
        with self.assertRaises(ValueError):
            mock_func()
        
        # 设置副作用：返回多个值
        mock_func.side_effect = [1, 2, 3]
        self.assertEqual(mock_func(), 1)
        self.assertEqual(mock_func(), 2)
        self.assertEqual(mock_func(), 3)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

#### 3.5.2 修补对象：`patch`装饰器
`patch`用于临时替换对象的属性，最常用于修补模块中的函数或类：

```python
# patch_example.py
import unittest
from unittest.mock import patch
import requests

def get_weather(city):
    """调用外部API获取天气"""
    response = requests.get(f"https://api.weather.com/{city}")
    return response.json()

class TestWeather(unittest.TestCase):
    @patch('requests.get')
    def test_get_weather(self, mock_get):
        # 设置模拟响应
        mock_response = MagicMock()
        mock_response.json.return_value = {"city": "Beijing", "temperature": 25}
        mock_get.return_value = mock_response
        
        # 调用待测试函数
        result = get_weather("Beijing")
        
        # 验证结果
        self.assertEqual(result["temperature"], 25)
        
        # 验证API调用
        mock_get.assert_called_once_with("https://api.weather.com/Beijing")

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

import unittest

### 3.6 异步代码测试
Python 3.8+引入了`IsolatedAsyncioTestCase`用于测试异步代码，Python 3.14.0对其进行了性能优化：

```python
# async_test.py
import unittest
import asyncio
from unittest.mock import AsyncMock, patch

async def async_add(a, b):
    await asyncio.sleep(0.1)
    return a + b

class TestAsyncCode(unittest.IsolatedAsyncioTestCase):
    async def asyncSetUp(self):
        """异步测试前的准备工作"""
        self.a = 2
        self.b = 3
    
    async def asyncTearDown(self):
        """异步测试后的清理工作"""
        del self.a
        del self.b
    
    async def test_async_add(self):
        result = await async_add(self.a, self.b)
        self.assertEqual(result, 5)
    
    @patch('asyncio.sleep', new_callable=AsyncMock)
    async def test_async_mock(self, mock_sleep):
        result = await async_add(2, 3)
        self.assertEqual(result, 5)
        mock_sleep.assert_called_once_with(0.1)

if __name__ == '__main__':
    unittest.main(verbosity=2)
```

## 四、实战案例：测试用户认证系统
### 4.1 需求描述
我们需要测试一个简单的用户认证系统，该系统提供以下功能：
1. 用户注册：验证用户名唯一性和密码强度
2. 用户登录：验证用户名和密码是否正确
3. 修改密码：验证旧密码并更新新密码

系统依赖一个简单的数据库存储用户信息，我们将使用`unittest.mock`来模拟数据库操作。

### 4.2 待测试的原始代码
```python
# auth_system.py
class UserDatabase:
    """用户数据库类"""
    def __init__(self):
        self.users = {}  # 格式: {username: {"password": password}}
    
    def get_user(self, username):
        """获取用户信息"""
        return self.users.get(username)
    
    def add_user(self, username, password):
        """添加新用户"""
        if username in self.users:
            raise ValueError("用户名已存在")
        self.users[username] = {"password": password}
    
    def update_password(self, username, new_password):
        """更新用户密码"""
        if username not in self.users:
            raise ValueError("用户不存在")
        self.users[username]["password"] = new_password

class AuthSystem:
    """用户认证系统"""
    def __init__(self, db=None):
        self.db = db or UserDatabase()
    
    def register(self, username, password):
        """用户注册"""
        if len(username) < 3:
            raise ValueError("用户名长度至少为3个字符")
        if len(password) < 6:
            raise ValueError("密码长度至少为6个字符")
        
        self.db.add_user(username, password)
        return True
    
    def login(self, username, password):
        """用户登录"""
        user = self.db.get_user(username)
        if not user:
            return False
        return user["password"] == password
    
    def change_password(self, username, old_password, new_password):
        """修改密码"""
        user = self.db.get_user(username)
        if not user:
            raise ValueError("用户不存在")
        if user["password"] != old_password:
            raise ValueError("旧密码错误")
        if len(new_password) < 6:
            raise ValueError("新密码长度至少为6个字符")
        
        self.db.update_password(username, new_password)
        return True
```

## 五、总结与扩展
### 5.1 核心知识点回顾
- unittest是Python标准库内置的xUnit风格单元测试框架
- 测试用例继承自`unittest.TestCase`，方法以`test_`开头
- 测试固件用于准备和清理测试环境，分为方法级、类级和模块级
- 丰富的断言方法用于验证测试结果，Python 3.14新增了`assertSequenceEqual(strict=True)`
- `unittest.mock`用于模拟依赖项，是单元测试的核心工具
- 支持跳过测试、预期失败、参数化测试和异步测试
- 测试套件用于组织多个测试用例，测试加载器用于自动发现测试

### 5.2 单元测试最佳实践
1. **测试独立性**：每个测试用例应该独立运行，不依赖其他测试的结果
2. **单一职责**：每个测试方法只测试一个功能点
3. **描述性命名**：使用清晰的测试方法名，说明测试的内容和预期结果
4. **覆盖边界条件**：测试正常情况、异常情况和边界条件
5. **使用模拟对象**：隔离外部依赖，确保测试只关注待测试的代码
6. **保持测试快速**：单元测试应该快速运行，避免不必要的等待
7. **定期运行测试**：将测试集成到开发流程和持续集成系统中

### 5.3 扩展工具推荐
- **pytest**：更强大、更灵活的测试框架，兼容unittest测试用例
- **coverage.py**：代码覆盖率分析工具
- **hypothesis**：基于属性的测试框架，自动生成测试用例
- **pytest-mock**：pytest的mock插件，比unittest.mock更易用
- **tox**：自动化测试工具，支持在多个Python版本中运行测试
